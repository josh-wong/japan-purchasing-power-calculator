# Japan Purchasing Power Calculator

**Design document · v1.0**

## Architecture

Build a single page with HTML, CSS, and TypeScript using Vite. The form owns in-memory state, a pure calculation module derives the outputs, and the view formats and displays them. GitHub Actions validates the code and publishes Vite's `dist/` directory to GitHub Pages. Set Vite's `base` to `/japan-purchasing-power-calculator/` for the project site on `080f53.com`. Use `/` if serving the app at a domain root. Resolve the exchange-rate JSON path against `import.meta.env.BASE_URL`.

| Responsibility | Suggested location |
| --- | --- |
| Page structure and styles | `index.html`, `privacy.html`, `src/styles.css` |
| Appearance preference applied before first paint | `public/theme.js` |
| Form state, events, formatting, and rendering | `src/main.ts` |
| Numeric validation and calculation | `src/calculator.ts` |
| Consent record, opt-out signals, and analytics loading | `src/analytics.ts` |
| Opt-in panel and **Analytics settings** control | `src/consent-banner.ts` |
| Multi-page build inputs | `vite.config.ts` |
| Fetch and validate reference rates for deployment | `scripts/update-rates.mjs` |
| Verify changes and deploy the site | `.github/workflows/pages.yml` |

Keep the preset, price, income in yen, and selected currency in the form. A preset updates the price field and recalculates the results. A manual change that differs from the selected example clears the selection and displays the **Choose an example** placeholder. Keep a map of comparison income amounts keyed by currency for the current visit. An unvisited currency starts with the equivalent of the built-in US$4,000 example, rounded up to the nearest thousand, or ten thousand for amounts of at least 100,000. Directly below the **Comparison income** legend, show “Use the example or enter a monthly income in the selected currency.” Associate this guidance with the fieldset and its income input. Keep it visible while editing and switching currency. Use neutral wording that does not ask for personal income. Returning to a previously used currency restores its amount for that visit. Reset restores the JP¥5,000 attraction ticket and both starting income amounts. Store inputs in memory only. Browser storage holds only the theme preference and the analytics consent record.

## Calculations and states

Define `priceJpy` as the purchase price. `japanMonthly` and `comparisonMonthly` are monthly take-home income amounts in yen and the comparison currency, respectively.

| Output | Calculation |
| --- | --- |
| Converted price | `priceJpy × (target units per EUR ÷ JPY per EUR)` |
| Equivalent cost based on income | `(priceJpy ÷ japanMonthly) × comparisonMonthly` |
| Percentage of monthly take-home income in yen | `(priceJpy ÷ japanMonthly) × 100` |
| Percentage of comparison income | `(unrounded converted price ÷ comparisonMonthly) × 100` |

Use 1 for EUR's units per EUR. Round only for display. Use `Intl.NumberFormat` with the currency's standard minor-unit precision for both the minimum and maximum number of decimal places. Use a familiar symbol where one is available and keep ISO currency codes in the picker and labels. Use `formatToParts()` to override ambiguous symbols, including US$ for USD and JP¥ for JPY. Fall back to the currency code when it serves as the currency marker, as with CHF. Show amounts such as US$100.00, JP¥10,000, €100.00, and ₩10,000. Normalize valid field values on blur, leaving the cursor and text alone while users type. Format percentages with up to two decimal places, using “<0.01%” for positive shares below that threshold. Show percentages above 100% in full.

- Accept zero or a positive purchase price and positive income amounts. Accept ungrouped digits or comma groups with one to three leading digits followed by groups of three, as in `1,234`. Show an inline error for misplaced commas. Use a period for decimals. Accept full-width digits, commas, and periods by normalizing them before parsing. Allow up to two decimal places in all fields and use the currency's standard precision as the limit if it is greater. Limit the whole-number part to 12 digits. On blur, group digits and preserve any fractional digits needed to represent the input exactly. Use standard currency precision for calculated monetary results.
- A blank field is incomplete. Malformed or out-of-range input shows an inline message. Continue showing any independently computable output.
- A zero purchase price produces zero for results with valid inputs. A zero income amount shows an inline error and suppresses results that depend on it.
- Calculate the converted price from the purchase price and exchange rate alone. If the rate is missing, show “Exchange rate unavailable.” The percentage of income in yen and the equivalent cost can still be calculated from the entered amounts. The comparison income percentage requires the converted price. Keep each comparison income tied to the currency in which it was entered.

## Rate data and deployment

Use the ECB daily XML feed. Convert it to same-origin JSON containing the publication date, source, and positive units-per-EUR values keyed by ISO currency code. Derive the supported currency list from the feed, including EUR and excluding JPY. Bundle the last verified set of supported currency codes so the picker works if the rates asset cannot load. The ECB publishes reference rates on working days, so weekends can show the latest working-day rate.

1. Set **Settings → Pages → Source** to **GitHub Actions**. Run checks on pull requests. Build and publish from the default branch on pushes, on a daily schedule after the ECB's usual publication time, and on manual dispatch. Use `20 17 * * *` with `Europe/Brussels` for the scheduled refresh.
2. Fetch the XML and verify the date and the numeric rates, including JPY units per EUR. Build the site with its verified snapshot. Upload `dist/` with `actions/upload-pages-artifact`, then publish with `actions/deploy-pages` in the `github-pages` environment. Give the deploy job `pages: write` and `id-token: write`. Serialize production runs and skip superseded default-branch builds. If fetching or validation fails, stop before publication so the previous site and snapshot remain available.
3. Show the publication date and a visible link to the [ECB reference rates](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) below the converted amount. Spell out the month in full, as in November 11, 2026. Open the source in a new tab so the visitor can return to their scenario. Mark a snapshot older than seven calendar days as outdated while still showing its dated estimate. Show the numeric currency pair in a light crimson callout sized to its text directly below the monetary amount in **Price at the exchange rate**, before the source and date. Align it with the amount and omit the trailing period. Use up to six significant digits. Label it **Exchange rate used** for every available rate. The displayed conversion represents a working-day reference rate before card or exchange fees. Intraday quotes would require a provider with a faster publishing schedule. Fetch those rates from CI or a server-side endpoint if the provider requires an API key.

GitHub disables scheduled workflows in public repositories after 60 days without repository activity. If the schedule is disabled, re-enable the workflow in **Actions** and run it manually to refresh the snapshot.

## Privacy and usage analytics

The calculator never sends or stores the amounts visitors enter, the currencies or presets they choose, or the results. Its only data request is the same-origin rate snapshot. Google Analytics 4 is the only third-party service, and it runs only after the visitor opts in. Opt-in applies to every visitor regardless of location, which satisfies the ePrivacy Directive, GDPR, UK PECR, and stricter state and national rules without geolocation.

Provide the GA4 measurement ID at build time as `VITE_GA_MEASUREMENT_ID`, set from the `GA_MEASUREMENT_ID` repository variable in the Pages workflow. Each entry script loads `src/consent-banner.ts` through a dynamic import guarded by that variable. Builds without an ID, including forks, local builds, and pull request checks, contain no consent panel, settings control, or analytics code.

1. On load, read the consent record from browser storage. It holds the choice, the time it was made, and the notice version. Discard records that are malformed, dated in the future, older than 12 months, or from an earlier `consentVersion`.
2. If the browser sends Global Privacy Control or Do Not Track, treat it as a decline. Don't show the panel or load analytics, even over an earlier opt-in.
3. Without a valid choice or signal, show the opt-in panel. Without consent, load no Google script, make no Google request, and set no cookies. Delete any leftover analytics cookies with this app's prefix.
4. After **Allow analytics**, store the choice and load `gtag.js`. Set Consent Mode defaults that deny advertising storage, user data, and personalization. Turn off Google signals and ad personalization signals. Use host-only cookies (`cookie_domain: 'none'`) limited to Vite's base path, with a 12-month lifetime and the `jppc` prefix (`cookie_prefix`). The app shares the `www.080f53.com` origin with other sites that use unprefixed `_ga` cookies, so the prefix keeps it from reading or deleting theirs. Send `page_location` as the origin and path plus `utm_*` campaign parameters only. Don't send custom events or parameters.
5. After **Decline**, or a withdrawal through **Analytics settings**, store the choice, set `window['ga-disable-<ID>']`, update consent to denied, and delete this app's prefixed cookies (`jppc_ga` and `jppc_ga_*`) at the base path. Never delete unprefixed `_ga` cookies. If storage is unavailable, apply the choice for the current visit and ask again on the next.

Configure the GA4 property to match the privacy notice. Turn off Google signals, the Google Ads and other product links, User-ID, and the enhanced measurement form-interaction and site-search events. Set event data retention to 2 months, and accept the data processing terms in **Admin → Account settings**. Increase `consentVersion` and update the privacy notice whenever what analytics collects changes, so every visitor is asked again.

Show the opt-in panel as the first element of the page, before the header, in the normal document flow so it never covers focused content. Title it **Usage analytics** and explain in one paragraph that, with permission, the site uses Google Analytics cookies to count visits and see which pages people use, and that it never sends entered amounts or chosen options. Link to the privacy notice, except on the notice itself. Give **Allow analytics** and **Decline** identical styling, a 2.75rem minimum height, and visible focus; stack them to full width at narrow widths. When the panel closes after a choice, move focus to the page heading, or back to **Analytics settings** if the visitor opened the panel from there. Announce the outcome politely, including "for this visit" when storage is unavailable.

Add **Privacy notice** and **Analytics settings** to the footer on both pages. **Analytics settings** reopens the panel with the current choice. When a privacy signal is active, the panel explains that analytics stays off and offers only **Close**. `privacy.html` uses the same header, theme control, and footer as the calculator, links back to it, and covers what stays in the browser, what analytics collects, cookies, purpose and legal basis, recipients and international transfers, retention, choices, rights, contact, and changes.

## Interface and verification

Show **Japan Purchasing Power Calculator** in the site header and browser tab. Use **How much of a monthly income in yen would that purchase take?** as the page heading. Use “Enter a purchase price and a monthly income in yen. See what percentage of that income the purchase takes, and what the same percentage would amount to on an income in another currency.” as the introduction.

Place two borderless icon controls at the right edge of the header. Give each a 2.75rem square target, a subtle theme-aware hover tint, and a visible keyboard focus ring. Put the [GitHub mark](https://primer.style/octicons/icon/mark-github-16/) immediately to the left of the appearance button and link it to the [source repository](https://github.com/josh-wong/japan-purchasing-power-calculator) in a new tab. Give it the tooltip “View source on GitHub” and include the new-tab behavior in its accessible label. Cycle through **System**, **Light**, and **Dark**, using monitor, sun, and moon icons. Give the button a tooltip and accessible label that state the current mode and the next mode. Let the site title wrap on narrow screens. Use `prefers-color-scheme` to resolve **System** and respond to device appearance changes. Read the theme preference from browser storage before the first paint. If storage is unavailable, let users switch themes for the current visit. Keep the theme setting independent of the scenario reset.

Place the **Try an example** picker above a full-width yen price field. Under **Monthly take-home income**, show a full-width **Income in yen** field followed by a **Comparison income** fieldset. Within that group, place **Comparison currency** immediately before **Monthly income** in both reading and keyboard order. Keep the currency and income controls side by side where space permits and stack them on narrow screens. Include the selected currency code in the monthly income label. Put the note about example prices directly below the **Try an example** label and above the dropdown. Set field guidance, validation messages, and secondary result notes, including the exchange-rate source and date, to `0.875rem` (14 px at the default root size). Use **Comparison currency** in the picker and **Monthly income** for the amount within the **Comparison income** group. Use one guidance paragraph: “Enter monthly income after taxes and other deductions. The incomes can be real or hypothetical. The prefilled amounts are editable examples, not national averages.” Include “Your inputs stay in this browser and aren’t saved.” in the footer disclaimer. Label the reset action **Restore defaults**; it restores the default price, USD currency, and incomes and clears remembered comparison incomes.

Lead with **Same share of income** in the crimson panel. Show the equivalent amount in the largest type. Below it, connect the entered yen price, its share of the entered income in yen, and the equivalent cost: “JP¥5,000 is about 2% of the entered income in yen. The same share of the comparison income is US$80.00.” for the default example. Preserve fractional yen in this explanation when entered. Use “about” for displayed positive percentages of 0.01% or more, and retain “less than 0.01%” for smaller positive shares. Calculate the equivalent amount with the unrounded share. When an income is missing, prompt for it in that panel. Put the **Price at the exchange rate** in smaller type below the main result. Show its ECB link and full date below the converted amount at every screen width. Keep the two side-by-side figures under **Share of monthly take-home income** below the conversion. Add “Yen price ÷ income in yen” and “Converted price ÷ comparison income” below their respective figures so their different price bases remain clear. Automatic screen-reader updates label the main amount “Equivalent cost at the same share of income” and announce only that amount and the price at the exchange rate, plus a missing-input prompt or unavailable-rate status when needed. Stack the form and result panels on small screens. Use native controls with visible labels and focus states, inline field errors shown after leaving a field and cleared when editing resumes, and a polite result announcement after a pause in typing. Use three bullets in a collapsed **How it’s calculated** section for the converted price, the income-based equivalent, and the comparison income percentage. In the equivalent-cost bullet, explain that the same percentage represents more money when comparison income rises.

Take the visual palette from the Hinomaru's deep red and white. Use warm white for the page, white for form surfaces, crimson for interactive accents, and deep crimson behind the main result. The light theme uses `#FCF8F6`, `#FFFFFF`, `#A71936`, and `#87152C` for those roles. The dark theme uses charcoal page and panel backgrounds, a deeper burgundy behind the main result, light text, and lighter crimson accents for links, errors, and focus. Apply the themed background to both the root and the full-height body so the page stays dark below the calculator.

Use the adjacent [interactive mockup](v1.0-gui-mockup.html) as the layout and interaction reference. It includes a dated ECB snapshot for a subset of currencies and makes one keyless request for the latest ECB rates through Frankfurter on open. It accepts positive rates dated the same day as the JPY rate and falls back to the bundled pair if the request fails or that pair is unavailable. The request carries currency codes only. The deployed app obtains the rates directly from the ECB in GitHub Actions and serves them from the same origin. The mockup has no analytics, consent panel, or privacy notice; follow the Privacy and usage analytics section for those.

Verify the default example, preset selection and manual edits, both income shares, currency restoration, missing and zero income, grouped and fractional entries, misplaced commas in the whole-number portion and regrouping on blur, invalid values, symbol and minor-unit formatting, shares above 100%, stale and missing rates, and operation at root and project Pages paths. Verify the interface on a narrow phone viewport and with keyboard navigation. Verify theme switching, live device appearance changes in **System**, and preference restoration after reload. Verify that no Google request or cookie occurs before opt-in, that privacy signals and blocked storage behave as described, that withdrawal deletes the app's prefixed analytics cookies and leaves other sites' `_ga` cookies, that no calculator value appears in any analytics request, and that builds without a measurement ID contain no analytics code.

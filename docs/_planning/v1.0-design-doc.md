# Japan Purchasing Power Calculator

**Design document · v1.0**

## Architecture

Build a single page with HTML, CSS, and TypeScript using Vite. The form owns in-memory state, a pure calculation module derives the outputs, and the view formats and displays them. GitHub Actions validates the code and publishes Vite's `dist/` directory to GitHub Pages. Set Vite's `base` to `/japan-purchasing-power-calculator/` for the project site on `080f53.com`. Use `/` if serving the app at a domain root. Resolve the exchange-rate JSON path against `import.meta.env.BASE_URL`.

| Responsibility | Suggested location |
| --- | --- |
| Page structure and styles | `index.html`, `src/styles.css` |
| Form state, events, formatting, and rendering | `src/main.ts` |
| Numeric validation and calculation | `src/calculator.ts` |
| Fetch and validate reference rates for deployment | `scripts/update-rates.mjs` |
| Verify changes and deploy the site | `.github/workflows/pages.yml` |

Keep the preset, price, income in Japan, and selected currency in the form. A preset updates the price field and recalculates the results. A manual change that differs from the selected example clears the selection and displays the **Choose an example** placeholder. Keep a map of comparison income amounts keyed by currency for the current visit. An unvisited currency starts with a blank amount, apart from the built-in USD example. Returning to a previously used currency restores its amount for that visit. Reset restores the JP¥5,000 attraction ticket and both starting pay amounts. Store inputs in memory only.

## Calculations and states

Define `priceJpy` as the purchase price. `japanMonthly` and `comparisonMonthly` are monthly take-home pay amounts in yen and the comparison currency, respectively.

| Output | Calculation |
| --- | --- |
| Converted price | `priceJpy × (target units per EUR ÷ JPY per EUR)` |
| Equivalent cost based on income | `(priceJpy ÷ japanMonthly) × comparisonMonthly` |
| Percentage of monthly take-home pay in Japan | `(priceJpy ÷ japanMonthly) × 100` |
| Percentage of comparison income | `(unrounded converted price ÷ comparisonMonthly) × 100` |

Use 1 for EUR's units per EUR. Round only for display. Use `Intl.NumberFormat` with the currency's standard minor-unit precision for both the minimum and maximum number of decimal places. Use a familiar symbol where one is available and keep ISO currency codes in the picker and labels. Use `formatToParts()` to override ambiguous symbols, including US$ for USD and JP¥ for JPY. Fall back to the currency code when it serves as the currency marker, as with CHF. Show amounts such as US$100.00, JP¥10,000, €100.00, and ₩10,000. Normalize valid field values on blur, leaving the cursor and text alone while users type. Format percentages with up to two decimal places, using “<0.01%” for positive shares below that threshold. Show percentages above 100% in full.

- Accept zero or a positive purchase price and positive pay amounts. Accept ungrouped digits or comma groups with one to three leading digits followed by groups of three, as in `1,234`. Show an inline error for misplaced commas. Use a period for decimals. Accept full-width digits, commas, and periods by normalizing them before parsing. Allow up to two decimal places in all fields and use the currency's standard precision as the limit if it is greater. Limit the whole-number part to 12 digits. On blur, group digits and preserve any fractional digits needed to represent the input exactly. Use standard currency precision for calculated monetary results.
- A blank field is incomplete. Malformed or out-of-range input shows an inline message. Continue showing any independently computable output.
- A zero purchase price produces zero for results with valid inputs. A zero pay amount shows an inline error and suppresses results that depend on it.
- Calculate the converted price from the purchase price and exchange rate alone. If the rate is missing, show “Exchange rate unavailable.” The percentage of income in Japan and the equivalent cost can still be calculated from the entered amounts. The comparison income percentage requires the converted price. Keep each comparison income tied to the currency in which it was entered.

## Rate data and deployment

Use the ECB daily XML feed. Convert it to same-origin JSON containing the publication date, source, and positive units-per-EUR values keyed by ISO currency code. Derive the supported currency list from the feed, including EUR and excluding JPY. Bundle the last verified set of supported currency codes so the picker works if the rates asset cannot load. The ECB publishes reference rates on working days, so weekends can show the latest working-day rate.

1. Set **Settings → Pages → Source** to **GitHub Actions**. Run checks on pull requests. Build and publish from the default branch on pushes, on a daily schedule after the ECB's usual publication time, and on manual dispatch. Use `20 17 * * *` with `Europe/Brussels` for the scheduled refresh.
2. Fetch the XML and verify the date and the numeric rates, including JPY units per EUR. Build the site with its verified snapshot. Upload `dist/` with `actions/upload-pages-artifact`, then publish with `actions/deploy-pages` in the `github-pages` environment. Give the deploy job `pages: write` and `id-token: write`. Serialize production runs and skip superseded default-branch builds. If fetching or validation fails, stop before publication so the previous site and snapshot remain available.
3. Show the publication date and a visible link to the [ECB reference rates](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) below the converted amount. Spell out the month in full, as in November 11, 2026. Open the source in a new tab so the visitor can return to their scenario. Mark a snapshot older than seven calendar days as outdated while still showing its dated estimate. Show the numeric currency pair in an indented light crimson callout sized to its text under the conversion bullet in **How it’s calculated**. Use up to six significant digits. Label it **Exchange rate used** for every available rate. The displayed conversion represents a working-day reference rate before card or exchange fees. Intraday quotes would require a provider with a faster publishing schedule. Fetch those rates from CI or a server-side endpoint if the provider requires an API key.

GitHub disables scheduled workflows in public repositories after 60 days without repository activity. If the schedule is disabled, re-enable the workflow in **Actions** and run it manually to refresh the snapshot.

## Interface and verification

Show **Japan Purchasing Power Calculator** in the site header and browser tab. Use **How does a purchase in Japan compare with monthly income?** as the page heading. Use “Compare a purchase with monthly take-home pay in Japan and another currency. See its price at the exchange rate too.” as the introduction.

Place two borderless icon controls at the right edge of the header. Give each a 2.75rem square target, a subtle theme-aware hover tint, and a visible keyboard focus ring. Put the [GitHub mark](https://primer.style/octicons/icon/mark-github-16/) immediately to the left of the appearance button and link it to the [source repository](https://github.com/josh-wong/japan-purchasing-power-calculator) in a new tab. Give it the tooltip “View source on GitHub” and include the new-tab behavior in its accessible label. Cycle through **System**, **Light**, and **Dark**, using monitor, sun, and moon icons. Give the button a tooltip and accessible label that state the current mode and the next mode. Let the site title wrap on narrow screens. Use `prefers-color-scheme` to resolve **System** and respond to device appearance changes. Read the theme preference from browser storage before the first paint. If storage is unavailable, let users switch themes for the current visit. Keep the theme setting independent of the scenario reset.

Place the **Try an example** picker above the price and currency fields. Put the note about example prices directly below the **Try an example** label and above the dropdown. Set field guidance, validation messages, and secondary result notes, including the exchange-rate source and date, to `0.875rem` (14 px at the default root size). Use **Comparison currency** in the picker and **Japan income** and **Comparison income** under **Monthly take-home pay**. Use one guidance paragraph: “Enter monthly pay after taxes and other deductions. The prefilled amounts are editable examples, not national averages.” Include “Your inputs stay in this browser and aren’t saved.” in the footer disclaimer. Label the reset action **Restore defaults**; it restores the default price, USD currency, and incomes and clears remembered comparison incomes.

Lead with **Equivalent cost based on income** in the crimson panel. Show the equivalent amount in the largest type. Below it, describe the share of monthly pay the purchase takes in Japan and explain the amount that same share represents with “That’s like spending US$80.00 from the comparison income.” for the default example. Use “about” for displayed positive percentages of 0.01% or more, and retain “less than 0.01%” for smaller positive shares. Calculate the equivalent amount with the unrounded share. When an income is missing, prompt for it in that panel. Put the **Price at the exchange rate** in smaller type below the main result. Show its ECB link and full date below the converted amount at every screen width. Keep the two side-by-side figures under **Percentage of monthly take-home pay at the exchange rate** below the conversion. Add “At the converted price” to the comparison-income figure and keep that context available when reading the results. Automatic screen-reader updates announce only the equivalent cost and the price at the exchange rate, plus a missing-input prompt or unavailable-rate status when needed. Stack the form and result panels on small screens. Use native controls with visible labels and focus states, inline field errors shown after leaving a field and cleared when editing resumes, and a polite result announcement after a pause in typing. Use three bullets in a collapsed **How it’s calculated** section for the converted price, the income-based equivalent, and the comparison income percentage. In the equivalent-cost bullet, explain that the same percentage represents more money when comparison income rises.

Take the visual palette from the Hinomaru's deep red and white. Use warm white for the page, white for form surfaces, crimson for interactive accents, and deep crimson behind the main result. The light theme uses `#FCF8F6`, `#FFFFFF`, `#A71936`, and `#87152C` for those roles. The dark theme uses charcoal page and panel backgrounds, a deeper burgundy behind the main result, light text, and lighter crimson accents for links, errors, and focus. Apply the themed background to both the root and the full-height body so the page stays dark below the calculator.

Use the adjacent [interactive mockup](v1.0-gui-mockup.html) as the layout and interaction reference. It includes a dated ECB snapshot for a subset of currencies and makes one keyless request for the latest ECB rates through Frankfurter on open. It accepts positive rates dated the same day as the JPY rate and falls back to the bundled pair if the request fails or that pair is unavailable. The request carries currency codes only. The deployed app obtains the rates directly from the ECB in GitHub Actions and serves them from the same origin.

Verify the default example, preset selection and manual edits, both paycheck shares, currency restoration, missing and zero pay, grouped and fractional entries, invalid values, symbol and minor-unit formatting, shares above 100%, stale and missing rates, and operation at root and project Pages paths. Verify the interface on a narrow phone viewport and with keyboard navigation. Verify theme switching, live device appearance changes in **System**, and preference restoration after reload.
